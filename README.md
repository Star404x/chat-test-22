# Mini Photo Site

Небольшой адаптивный сайт для загрузки, хранения и отображения фотографий. Этот репозиторий содержит базовый Node.js/Express сервер и инструкции по локальному запуску и деплою на Heroku.

## Что в репозитории

- src/index.js — минимальный Express-сервер, служит статические файлы из `public/` и предоставляет `/api/health`.
- package.json — скрипты и зависимости.
- Procfile — инструкция для Heroku.

## Быстрый запуск локально

Требования:
- Node.js (>=14)
- npm или yarn

1. Установите зависимости:

   npm install

2. Для разработки (с авто-перезагрузкой, если установлен nodemon):

   npm run dev

3. Для продакшен-старта:

   npm start

4. Откройте http://localhost:3000 и проверьте http://localhost:3000/api/health

Если вам нужны переменные окружения, создайте файл `.env` и заполните необходимые ключи. В коде примерно используется только PORT (по умолчанию 3000).

## Деплой на Heroku (выбранная среда)

Heroku хорошо подходит для размещения этого Node.js приложения.

Предварительные шаги:
- Установите Heroku CLI: https://devcenter.heroku.com/articles/heroku-cli
- Авторизуйтесь: `heroku login`

Инструкция:

1. Создайте приложение на Heroku (в каталоге проекта):

   heroku create <your-app-name>

   Если имя не указывать, Heroku сгенерирует его автоматически.

2. Добавьте необходимые переменные окружения (например, доступ к хранилищу, секреты и т.п.):

   heroku config:set KEY=value --app <your-app-name>

3. Убедитесь, что у вас есть Procfile (в корне проекта):

   web: npm start

   (Procfile уже добавлен в этот репозиторий)

4. Закоммитьте изменения и запушьте в Heroku:

   git add .
   git commit -m "Deploy to Heroku"
   git push heroku main

   Примечание: если ваша основная ветка называется `master`, используйте `git push heroku master`.

5. Откройте приложение:

   heroku open --app <your-app-name>

Логи можно смотреть так:

   heroku logs --tail --app <your-app-name>

Советы:
- Для хранения фотографий в продакшене используйте внешний сервис (S3, Cloudinary и т.д.) и настройте соответствующие переменные окружения в Heroku.
- Если приложение использует базу данных, подключите Heroku Add-on (например, Heroku Postgres) или внешний сервис и укажите URL в конфигурации.

## Коротко о Netlify / GitHub Pages

- GitHub Pages и Netlify подходят для статических фронтенд-приложений. Если вы разделяете проект на frontend и backend, можно деплоить frontend на Netlify/GitHub Pages, а backend — на Heroku.
- Для чисто статического варианта просто положите собранный фронтенд в `public/` и разместите на Netlify или GitHub Pages.

## Troubleshooting

- "Port already in use": убедитесь, что переменная PORT не занята или измените её.
- Ошибки деплоя на Heroku: смотрите `heroku logs --tail`.

## Что дальше

Реализовать API для загрузки фотографий (эндпоинты для загрузки/списка/удаления), выбрать способ хранения (дисковая система, S3 или Cloudinary) и добавить простой frontend в `public/`.
