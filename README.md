# Leather - Mini-site

Этот репозиторий содержит серверную часть и настройки для тестирования и деплоя мини-сайта для демонстрации и продажи кожаных изделий.

Что включено на этом шаге:
- package.json с базовыми скриптами для запуска, тестов и CI
- Простой Express-сервер (src/index.js) для отдачи статических файлов и mock API
- GitHub Actions workflow для CI и деплоя на GitHub Pages
- Инструкции по кроссбраузерному тестированию, оптимизации и деплою

Быстрый старт
- Установите зависимости:

  npm install

- Для разработки с авто-перезапуском:

  npm run dev

- Для запуска в продакшн режиме:

  npm start

Оптимизация производительности (рекомендации)
- Сжатие изображений: WebP/AVIF для фотографий товаров. Прогрессивный JPEG для обратной совместимости.
- Минификация CSS/JS: используйте сборщик (esbuild/webpack/rollup) для production-бандлов.
- HTTP compression: в сервере включена compression middleware.
- Безопасность: helmet уже включен; дополнительно настройте CSP, X-Frame-Options и HSTS для продакшна.
- Кеширование: статические активы отдаются с Cache-Control; HTML помечается как no-cache для быстрой публикации изменений.
- Lazy-loading для изображений и критический CSS для ускорения первого рендера.

Кроссбраузерное тестирование
- Целевые браузеры: последние 2 версии Chrome, Firefox, Edge, Safari (iOS), а также мобильные браузеры Android.
- Локальные инструменты: Chrome DevTools, Firefox Developer Tools, Safari Web Inspector.
- Облачные сервисы: BrowserStack или LambdaTest для тестирования в реальной среде на разных устройствах.
- Автоматическое тестирование: интегрируйте end-to-end тесты (Playwright или Cypress) в CI, чтобы покрыть критичные пути (каталог, карточка товара, корзина, форма контакта).
- Тестовые сценарии: проверка отображения карточек, добавление в корзину, отправка формы контакта, адаптивность на разных разрешениях.

CI/CD
- В репозитории настроен GitHub Actions workflow (./github/workflows/ci.yml):
  - Запускает lint, тесты и сборку при push/pull_request в main.
  - В job 'deploy' используется peaceiris/actions-gh-pages для публикации содержимого public/ в GitHub Pages при пуше в main.
- Для деплоя на Vercel/Netlify: подключите репозиторий и настройте build command/ output directory. Vercel автоматически распознает Node.js проекты.
- Секреты: при деплое на сторонние хостинги добавьте токены в секреты репозитория.

Как подготовить к продакшен деплою
1. Добавьте фронтенд-билд в папку public/ (или настройте build script, который складывает артефакты в public/ или dist/).
2. Настройте реальные тесты (Jest + Playwright/Cypress) и добавьте их в npm test.
3. Настройте линтер (ESLint) и фиксеры, добавьте pre-commit hooks (husky) при необходимости.
4. Проверьте workflow YAML и замените publish_dir на директорию с билдом если отличается.
5. Настройте SSL и CDN (Cloudflare) для производительности и безопасности.
