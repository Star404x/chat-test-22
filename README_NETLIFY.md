Инструкция по деплою фронтенда на Netlify

Цель

Этот файл описывает, как задеплоить статическую сборку фронтенда приложения Mini Photo Site на Netlify. Предполагается, что бэкенд (API) развёрнут отдельно (например, на Heroku). В Netlify нужно задать URL вашего бэкенда через переменные окружения.

Требования

- Node.js и npm/yarn
- Netlify CLI (опционально, для CLI-деплоя): npm install -g netlify-cli
- Корень проекта содержит package.json со скриптом сборки (обычно: "build")

Подготовка

1. Укажите URL бэкенда в переменных окружения Netlify.
   - Перейдите в Netlify > Site settings > Build & deploy > Environment > Environment variables
   - Добавьте переменную, например API_BASE_URL или REACT_APP_API_BASE_URL, в зависимости от вашей реализации src/config.js
   - Значение должно быть публичным URL вашего бэкенда, например https://my-photo-api.herokuapp.com

2. SPA-маршрутизация

Если приложение — SPA (маршрутизация на клиенте), добавьте файл public/_redirects с содержимым:

/*    /index.html   200

Этот файл included в сборку и позволит корректно обрабатывать прямые переходы по URL.

Сборка и деплой через Netlify UI

1. В Netlify создайте новый сайт (New site from Git) и подключите ваш репозиторий.
2. Укажите команду сборки (например: npm run build) и папку-выход (обычно: build или dist).
3. В разделе Environment variables укажите API_BASE_URL как описано выше.
4. Запустите Deploy Site.

Деплой через Netlify CLI (локально)

Пример использования скрипта из репозитория:

1) Установите netlify-cli: npm install -g netlify-cli (или добавьте в devDependencies)
2) Выполните авторизацию (если первый раз): netlify login
3) Свяжите сайт с Netlify (однократно): netlify link --id <SITE_ID>
   либо пропустите, если будете указывать --site при деплое
4) Запустите автоматический скрипт деплоя из репозитория:

   node scripts/deploy_netlify.js --site <SITE_ID> [--prod]

Скрипт делает:
- npm run build
- netlify deploy --dir=build --site=<SITE_ID> (и --prod, если указана опция)

Примечания

- Убедитесь, что скрипт сборки пакует содержимое в папку, которую вы передаёте в netlify (обычно build/).
- Если у вас другой механизм переменных окружения (например .env), настройте соответствующим образом в Netlify UI — Netlify не читает локальные .env при билде на своей платформе.
- Если у вас есть приватные ключи/секреты, не храните их в репозитории; используйте Environment variables в Netlify или секреты в бэкенд-платформе.

Если бэкенд ещё не деплоен

Рекомендуется развернуть Node.js бэкенд на Heroku (или другом PaaS). После деплоя бэкенда: скопируйте публичный URL и добавьте его в переменные окружения Netlify (API_BASE_URL).
